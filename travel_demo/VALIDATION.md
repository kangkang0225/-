# 首版验证记录 · 2026-10-13

通过 12 项功能测试，使用模拟模型与临时目录：来源提示词可构建；固定字段 Markdown 与 JSON 节点往返；上传验证与原图完整保存；用户编辑原文保留；待处理轮次合并但不丢原话；运行中的旧草稿不覆盖纠正；停止取消任务、恢复与输入去重；失败后保留原始输入；禁止助手回应作为个人事实来源；排队时间受总超时约束；失败轮次保留客户端提交时间与缺失的回应终点，不记零等待；重试后台写作保留已结束的访谈状态。

使用现有 Key 真实验证了 MiniMax-M2.7 文字接口、MiniMax-M3 编码图片接口；图片为自建色块，不是参与者照片。另使用虚构测试讲述验证 Markdown 节点提取、片段充分性判断和最终节点清单，均可解析并保留用户话语序号。

在浏览器实际走通上传、开场、连续输入、后台记录、三版并列、直接改写并选用、正常收束和最终游记生成。测试会话标题明确标记“合成图片与虚构讲述”，可从本机记录复查。

发现并修订：模型会把完整讲述误作整场结束，且添加“最值回票价”等评价。补充了承接/收束动作区分与不擅自升华要求；复测能够继续提问。单次复测不证明此类问题彻底消失。三版自然表达与文学表达仍需逐例核查事实一致性。

两轮网页端首次实质回应分别约 20.0 秒和 34.5 秒。当前整段回复展示，首次实质回应与完整完成时间一致。它们是这次流程测试的观测值，样本不足以计算有意义的等待分布，未证明低等待体验达标。试测默认参数可调，后续优化应结合日志定位情绪、对话及排队耗时，并检验流式呈现的收益。

暂未进行真实游客评价、长篇游记质量对照、硬件/RFID接入或正式实验。实现、接口可用和用户体验效果分别报告。

后续修改回流复测时，记录员成功完成 Markdown 到 JSON 的解析；一次三版写作调用达到等待上限后失败，未覆盖用户保存的修改原文。该失败记录保留在 model_calls 中，点击恢复后真实模型再次成功返回三版，并保留已结束状态。这是实际观测到的异常，不应从等待评价中删除。

恢复生成的文学版曾省掉明确的“放松”感受并写成碎句。已加强提示词要求，但不能把修改提示词当作事实一致性已经验证；三版逐事实审查仍是需要真实材料开展的质量检查。
