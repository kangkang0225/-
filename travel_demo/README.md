# 旅行片刻 · 网页 Demo

在 StorySage 目录双击 `start-travel-demo.cmd`，然后打开 http://127.0.0.1:8765 。使用已配置在 StorySage `.env` 的 MiniMax Key。首版独立运行，不需要 MongoDB 或向量数据库；原 StorySage 的启动入口保留。

选取 JPG / PNG / WEBP 照片 → 连续访谈 → 后台整理节点与问题 → 三版微叙事并列 → 选择或直接修改 → 结束访谈 → 生成个人游记。可以立即停止，已有输入和原图会保留；恢复时继续未完成任务。会话结束不要求讲完全部照片。

当前文字模型读取 `MODEL_NAME`（默认 `MiniMax-M2.7`）；图片入口读取 `DEMO_VISION_MODEL`（默认 `MiniMax-M3`）。本次现有 Key 的两种模型调用均已用合成测试图验证。图片提交采用编码的缩小副本，原始文件完整存于 `data/travel_demo/<会话 id>/`。图片和访谈材料会发送给所配置的 MiniMax 接口；网页和本地记录本身不包含 API Key。不要把 `.env` 或整个 data 目录公开发布。

后续轮次不重新上传照片，使用首次线索、近期对话、已整理节点、实际问题及边界。原始多轮话语完整保存；近期对话范围可在设置中调整。没有 RFID、没有小程序接入。

后台记录最多一个执行任务，等待期间新增轮次并入下一次任务。节点由模型输出固定字段 Markdown，程序解析为 JSON；后续调用临时从 JSON 渲染 Markdown，不保存第二份长期节点文本。用户修正会使旧草稿失效；保存的编辑原文作为用户输入保留，更新节点不会无声覆盖编辑。新事实改变该片段后，需要重新确认新版，历史编辑仍存于记录。

访谈设置可以调整照片检查点、单次处理总等待、重试和恢复上限。照片时间从进入该照片时起包含系统等待；计时只影响下一次回应的收束判断，不自动打断用户。情绪识别与访谈是两次顺序调用，后台记录并行，当前回复整段展示，尚未采用逐字流式输出。因此首次实质回应与完成时间相同，不能按加载动画计为回复。

导出记录包含原始话语、用户编辑、节点的来源、问题状态、片段版本、最终生成快照与客户端等待记录（毫秒）；不包含图片文件本体。未选择风格的最终材料由记录员筛选；选择的片段参与生成。文学风格受事实限制，模型输出仍需要试测检查。

提示词来源、原文与适配范围见 [PROMPT_MAP.md](PROMPT_MAP.md)。当前实现是验证既定系统流程的首版，不等同于完成专利全部设备接入或取得实验效果。

修改 Python 提示词或归档来源后需重启服务。提示词版本绑定到本次启动的模块，避免编辑文件时误把正在运行的旧版本记成新版本。实际检查结果见 [VALIDATION.md](VALIDATION.md)。

## 检查

在 StorySage 目录运行：

```text
.venv\Scripts\python.exe -m unittest discover -s tests -p test_travel_demo.py -v
.venv\Scripts\python.exe scripts/check_travel_models.py
```

第一项使用模拟模型与临时目录验证功能；第二项使用现有 Key 真实调用文字和图片接口，只有合成图片与测试文字。若安装在新电脑，可将 `requirements-travel-demo.txt` 安装至原项目虚拟环境。
